# Operational cost of the proposed changes

1. **Label `media-processing` with baseline enforcement and harden `transcoder`.** This prevents the privileged/host-root configuration from being restored unnoticed and removes direct host filesystem and host network access. The current Deployment appears to depend on `/host` and host networking; the export does not explain why. The application team must replace that host-level input/connectivity with an approved interface and confirm it works before rollout. Until that migration is ready, the transcoder's host-level function may be interrupted. Do not apply as an uncoordinated production patch.
2. **Remove Pod create from `platform-deployer`.** This blocks `build/ci-runner` from launching any new platform Pods, including the `debug-shell-x7k2` action evidenced in the audit record. It preserves the CI runner's build-namespace Pod-create permission and its platform read permissions. Platform debugging or deployment workflows that rely on CI launching Pods need an approved alternative identity/process and a runbook update. The event proves the capability was used, but the export does not prove how often or which pipeline depends on it; stage the change with platform and CI owners.
3. **Change the admission binding from Audit to Deny (included in the fixed manifest).** This will reject privileged Deployment create/update requests caught by `disallow-privileged`. Existing violating workload updates and any legitimate exception will fail until corrected or explicitly redesigned. Test release pipelines against the policy first; preserve audit-only behavior during the rollout window if teams need to identify violations.
4. **Correct NetworkPolicy coverage and selector.** Fixing the payments selector and adding policies to currently uncovered namespaces can block traffic that currently flows. Map required ingress/egress flows with workload owners, test in a staging namespace, and roll out by namespace. `orders-api-ingress` already constrains ingress; tightening egress there would also require an explicit dependency inventory.

The fixed manifest snapshot includes the workload/namespace hardening, admission action change, and targeted Role change. NetworkPolicy selector and coverage changes remain recommendations pending workload-flow review before a safe production change.
