# Operational cost of the proposed changes

1. **Label `media-processing` with baseline enforcement and harden `transcoder`.** This prevents the privileged/host-root configuration from being restored unnoticed and removes direct host filesystem and host network access. The current Deployment appears to depend on `/host` and host networking; the export does not explain why. The application team must replace that host-level input/connectivity with an approved interface and confirm it works before rollout. Until that migration is ready, the transcoder's host-level function may be interrupted. Do not apply as an uncoordinated production patch.
2. **Remove `ci-runner-platform-deploy`.** This blocks `build/ci-runner` from creating platform Pods, including the `debug-shell-x7k2` action in the audit record, and removes its platform Pod, ConfigMap, and ServiceAccount reads. Its build Pod-create permission and legacy-billing Secret/ConfigMap reads remain. The audit proves the platform Pod-create capability was used, but not which pipeline depends on it or how often. Platform and CI owners should replace the workflow with a narrowly scoped deployment process and validate it in a change window.
3. **Change the admission binding from Audit to Deny (included in the fixed manifest).** This will reject privileged Deployment create/update requests caught by `disallow-privileged`. Existing violating workload updates and any legitimate exception will fail until corrected or explicitly redesigned. Test release pipelines against the policy first; preserve audit-only behavior during the rollout window if teams need to identify violations.
4. **Correct `payments-api-isolation` selector.** The fixed selector matches `payments-gateway`, `ledger`, and `payments-app-1`; with empty Ingress and Egress rule lists, it isolates all three in both directions when the CNI enforces NetworkPolicy. This can interrupt inbound service calls and outbound dependencies. Map flows with each workload owner, test in staging, and roll out with a rollback plan. Adding policies to namespaces with no policy is a separate change that also needs a flow inventory.

5. **Keep `orders-api-config` attached unless its workload is migrated.** In the export, `orders-api` runs as `orders-api-sa`, and RoleBinding `orders-api-config` in `prod` gives that account ConfigMap and Secret reads. Removing the binding leaves the running workload without those API permissions and may break its configuration or credential retrieval. No replacement mechanism is shown, so removal needs workload-owner confirmation and a change window; it is not included in the fixed snapshot.

The fixed manifest snapshot includes the media-processing namespace/workload hardening, admission action change, removal of the `ci-runner-platform-deploy` binding, and the corrected payments selector. The operational costs above need owner review before applying the snapshot to production.
