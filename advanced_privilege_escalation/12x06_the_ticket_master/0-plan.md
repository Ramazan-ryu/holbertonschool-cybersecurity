The objective is to establish an administrative session on Thornbury's database server by navigating the domain's trust and authentication architecture. This is not a local exploitation challenge; it is an identity problem. To reach the database server, I must systematically acquire an identity that the system already trusts, rather than attempting to break through the host's defenses.

**Cracking Strategy and Time Budget**
I will not crack every hash I collect. Cracking targets will be prioritized based strictly on their strategic value to the identity path—specifically focusing on service accounts, database administrators, or accounts with delegation rights. I will apply a strict time budget and stopping rule: any material that survives targeted dictionary attacks and standard rule permutations after two hours of compute time will be abandoned. Expending further hours on brute-forcing is a waste of the engagement's schedule.

**Using Recovered Material**
Recovered plaintext credentials will be used to request Ticket Granting Tickets (TGTs), perform targeted LDAP queries to map Active Directory permissions, and trace the exact access control lists governing the database server. 

When I recover authentication material—such as an NTLM hash or a valid Kerberos ticket—but cannot crack the plaintext password within the time budget, that material remains actionable. I will use Pass-the-Hash (PtH) or Pass-the-Ticket (PtT) techniques. By directly injecting these into my session, I can request service tickets or authenticate to target services exactly as if I had the plaintext.

**Operational Security and Prohibitions**
Before I have executed a single offensive command, I expect the domain controller to record my machine's baseline network presence. This includes DHCP lease requests, DNS queries, and background broadcast protocols (like LLMNR or NBT-NS) inherently generated by the base operating system upon connection.

Because this engagement requires subverting the authentication system to log in legitimately, the one thing I will absolutely not do is attempt local exploitation, memory corruption, or automated vulnerability scanning against the database server. Attacking the box directly triggers alarms and misses the objective entirely; the goal is to authenticate, not to exploit.
